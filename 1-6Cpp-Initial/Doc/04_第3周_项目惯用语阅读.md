## 知识点 1：`enum class` ——钥匙上刻房间名

### 先想这个问题

你的房间状态机：

```c
typedef enum {
    ST_ROOM_SAFE,
    ST_FIGHTING,
    ST_OPENING_CHEST,
    ST_DEAD
} RoomState;

typedef enum {
    EV_LOOK_AROUND,
    EV_ATTACK,
    EV_OPEN_CHEST,
    EV_HIT_BY_MONSTER
} RoomEvent;
```

C 的枚举值会漏到外围，本质是 `int`。`ST_DEAD` 和某个别的模块的 `ST_DEAD` 能撞车；你还可以写出 `state + event` 这种毫无意义的加法，编译器微笑放行。

`enum class`（scoped enumeration，作用域枚举）把每把钥匙刻上房间名：必须写 `RoomState::Dead`，不能当整数乱加。

### 它长什么样

```cpp
enum class RoomState { Safe, Fighting, OpeningChest, Dead };
enum class RoomEvent { LookAround, Attack, OpenChest, HitByMonster };

void process(RoomState s, RoomEvent e)
{
    if (s == RoomState::Dead) {
        return;
    }
    /* s == 3;            非法：不能和 int 随便比 */
    /* s == RoomEvent::Attack;  非法：不同类型 */
}
```

LCD 那一长串 `LCD_STATE_EXPOSURE` 前缀，用 `enum class LcdState { Exposure, PeelLift, ... }` 之后，前缀可以退休——名字空间已经由类型本身提供。

需要和底层协议里的整数对上时，再显式转：

```cpp
auto raw = static_cast<int>(LcdState::Exposure);
```

显式转换是在说「我知道自己在拆封条」，比 C 里默默当 `int` 用要老实。

### 本质

**`enum class` 是带作用域、默认不和整数互通的枚举，用来表达一组互斥名字。**

- **何时用到：** 状态机状态、事件、错误码、模式开关。几乎所有你现在用 C `enum` 的地方，读 C++ 项目时都会改成它。
- **系统位置：** 类型系统里「离散集合」这一格。比 `constexpr` 常量组更合适，因为比较和 `switch` 都按类型检查。
- **何时仍见普通 `enum`：** 老代码、要和 C ABI 互换、或必须当位掩码用的场合。见到不要惊讶，知道它更像 C 即可。

## 知识点 2：继承与虚函数 ——同一个按钮，不同电路

### 先想这个问题

假设 Z 轴有两种执行器：步进仿真、以后的真脉冲输出。它们都要 `move_to`、`is_busy`。C 里你通常会：

- 写两套函数，调用处 `switch (kind)`，或
- 函数指针表（手搓虚表）

C++ 把这张表收进语言：基类声明「我会这个按钮」，派生类各自接线。运行时用基类指针一按，真正跑哪条电路，查 vtable（virtual table，虚函数表）决定。

本周只要能 **读懂**，不必设计一套继承树。

### 它长什么样

```cpp
class ZAxis {
public:
    virtual ~ZAxis() = default;          /* 基类析构一般要虚 */ ？
    virtual void move_to(float z_mm) = 0; /* = 0：纯虚，派生类必须实现 */
    virtual bool is_busy() const = 0;
};

class SimulatedZAxis : public ZAxis {
public:
    void move_to(float z_mm) override;
    bool is_busy() const override;

private:
    float pos_mm_ = 0.0f;
    bool  busy_ = false;
};

void jog(ZAxis &axis)
{
    axis.move_to(1.0f);  /* 实际调用哪份代码，取决于 axis 真正的类型 */
}
```

读代码时的三个信号：

| 看到 | 含义 |
| --- | --- |
| `class B : public A` | B 是 A 的一种 |
| `virtual` | 这个按钮可能被派生类换线 |
| `override` | 作者明确说：我在覆盖基类那个按钮 |

没有 `virtual` 的继承，多半只是复用代码，调用仍按静态类型走——别自动脑补多态。

虚函数有代价：对象里多一个 vptr（指向虚表的指针），调用多一次间接跳转。固件里该用还是会用，但不会给每个 getter 都标 `virtual`。

### 本质

**虚函数是*运行期*多态：接口在基类，实现到对象真正的类型里查表。**

- **何时用到（读）：** 驱动抽象、插件、策略切换。看到基类指针/引用调用 `virtual` 函数，就知道「现在还不能确定汇编会跳到哪」。
- **系统位置：** 面向对象这条轴的运行期一侧。第 1 周的重载、下面的模板，是编译期多态。两条路都能「同一套说法、多种实现」，付钱的时间点不同。
- **本轮不做：** 多重继承、虚继承、纯设计模式讨论。见到 `virtual` 能翻译成「可能走虚表」就够。

## 知识点 3：模板 ——类型安全的「按需复印」

### 先想这个问题

你写过两种宏：

```c
#define max(x, y) ({ typeof(x) _x = (x); typeof(y) _y = (y); _x > _y ? _x : _y; })
#define min_t(type, x, y) ({ type _x = (x); type _y = (y); _x < _y ? _x : _y; })
```

第一段用 GNU `typeof` 偷类型，第二段让调用者把类型当参数喂进来。宏仍然是复印文本，副作用、优先级、报错信息都 magically 糟糕。

模板（template）是语言正统的「按类型复印」：编译器看到 `max_of(3, 4)` 就生成一份 `int` 版，看到 `max_of(3.0f, 4.0f)` 再生成一份 `float` 版。类型还在，报错也是类型系统的报错。

### 它长什么样

```cpp
template <typename T>
T max_of(T a, T b)
{
    return a > b ? a : b;
}

template <typename T>
struct Vec2 {
    T x;
    T y;
};

void demo()
{
    auto m = max_of(3, 4);           /* 编译器生成 max_of<int> */
    Vec2<float> v{1.0f, 2.0f};       /* 一个元素为 float 的二维向量 */
}
```

读项目时的脑内展开：

```text
std::vector<int>     →  元素是 int 的动态数组
std::unique_ptr<File> → 独占一个 File 的智能指针
```

尖括号里的是 **模板实参**。先把它读成「什么的什么」，不要一上来追模板特化、SFINAE。

函数模板几乎总是写在头文件里——因为编译器要在每个调用点看到完整定义才能复印。这和你在 `declaration.h` 里放 `static inline` 是同一类「必须让调用方看见函数体」的需求，但链接模型更干净：`inline` / 模板允许相同定义出现在多个 `.o` 里，由链接器归并。

### 本质

**模板是编译期的类型参数化：一份代码图样，按类型生成具体函数或类。**

- **何时用到：** 算法或容器不关心元素具体是什么，只关心它支持某些操作（能比较、能拷贝）。读代码远比写复杂模板常见。
- **系统位置：** 泛型编程（generic programming）的核心装置，标准库（vector、sort、unique_ptr）几乎全靠它。和宏同属「生成代码」，但模板活在类型系统里。
- **本轮不做：** 模板元编程、变参模板深水、Concepts。看到看不懂的一长串 `template <...>` 先跳过实现，去看它暴露的名字。

## 知识点 4：`auto` 与范围 for ——少写、少写错

### 先想这个问题

C 里遍历你很熟：

```c
for (int i = 0; i < n; ++i) {
    use(buf[i]);
}
```

下标能写飞。类型名一旦变成 `std::map<int, std::vector<float>>::iterator`，人会先被名字打倒。

`auto` 让编译器填类型（你用过 `typeof` 问类型，`auto` 是「问完直接当变量类型」）。范围 for（range-based for）则说：别管下标，把容器里每个元素给我。

### 它长什么样

```cpp
#include <vector>

void dump(const std::vector<float> &samples)
{
    for (auto v : samples) {          /* v 是每个元素的拷贝 */
        (void)v;
    }
    for (auto &v : samples) {         /* 引用：可改原元素；这里容器是 const，实际是 const float& */
        (void)v;
    }
    for (const auto &v : samples) {   /* 只读、不拷贝，读大对象时常用 */
        (void)v;
    }
}
```

`auto` 不是动态类型。类型在编译期就定死了，只是你懒得把名字写出来。初始化是什么，它就是什么——所以 **必须初始化**。

### 本质

**`auto` 是编译期类型推导；范围 for 是「遍历这个范围」的语法糖。**

- **何时用到：** 类型又长又丑、或写出来反而挡视线。返回类型要当接口文档时，仍应显式写出，别处处 `auto` 装神秘。
- **系统位置：** 属于「让编译器做书记员」的语法层，不改变对象模型。后面的 lambda、模板实例里会大量出现 `auto`。

## 知识点 5：lambda ——当场写的回调

### 先想这个问题

C 的回调是函数指针。函数必须长在别处，还不能方便地夹带局部变量（除非塞进 `void *userdata`，而你已经知道 C++ 有多讨厌来路不明的 `void *`）。

lambda expression（lambda 表达式，匿名函数对象）允许你在调用点当场写一段可调用的代码，并能捕获附近的变量。

### 它长什么样

```cpp
#include <algorithm>
#include <vector>

void keep_contact(std::vector<float> &pressures, float threshold)
{
    /* 删掉所有低于阈值的采样：谓词写在调用点 */
    pressures.erase(
        std::remove_if(
            pressures.begin(),
            pressures.end(),
            [threshold](float p) { return p < threshold; }),
        pressures.end());
}
```

`[threshold]` 是捕获列表：把外面的 `threshold` 按值收进这个小函数对象里。`[]` 什么都不抓，`[&]` 按引用抓（要确保引用的对象活得比 lambda 久）。

固件里函数指针仍然到处都是。读到 lambda 时把它还原成「一个只有 `operator()` 的小 struct」即可，不必先学 `std::function` 的开销细节。

### 本质

**lambda 是在使用点定义的函数对象，用来把短回调就地写清。**

- **何时用到：** `sort` / `find_if` 的比较规则、一次性回调、把「这段逻辑只在这里有意义」钉在调用点。超过几行就应升格成具名函数。
- **系统位置：** 函数对象这条轴的语法糖。它让标准库算法能吃「任意可调用物」，而不必你先声明一个 `elem_compare`。
- **和函数指针：** 函数指针是 C ABI 友好的裸地址；lambda 带捕获时不能直接转成函数指针。跨 C 边界仍用 `extern "C"` 函数。

## 打开陌生 `.cpp` 的扫描顺序（带着本周眼镜）

1. `namespace` / `#include`
2. `enum class` 还是普通 `enum`
3. `class` 有没有 `virtual` ——有则可能是接口，无则可能是数据+操作
4. 尖括号 `<T>` ——当「什么的什么」读
5. `auto` / 范围 for / lambda ——语法糖，还原成类型和回调即可
6. 宏和 `#ifdef` ——你已经熟，固件里不会消失
