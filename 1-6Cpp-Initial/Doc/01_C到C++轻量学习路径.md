# 从 C 到 C++：轻量系统学习路径

> 面向已经比较全面掌握 C 的读者。目标是**能读懂项目里的 C++ 源码、能小改、能跟现代习惯对上号**，而不是成为 C++ 语言律师。
>
> 文档版本：2026-08

---

## 0. 这份文档怎么用

- 主线只认 **1 本书 + 1 个免费教程 + 1 个查询手册**。其余都是按需查阅。
- 标准目标先锁定 **C++17**（C++17，2017 年 ISO 标准）。读到 C++20 的名字时知道它是什么即可，不必深挖。
- 每周投入大约 4～6 小时，大约 **4 周**能过完主干。再花 1～2 周对照自己仓库里的 C 代码做映射练习。
- 遇到不懂的语法，先查 [cppreference](https://zh.cppreference.com/w/cpp)，不要去搜随机博客。

## 1. 你的基础，决定了怎么学

本仓库已经覆盖的 C 能力，大致是：

| 你已经会的 | 对应目录 | 学 C++ 时怎么用 |
|---|---|---|
| PID（Proportional-Integral-Derivative，比例-积分-微分）离散控制 | `1-1PID_Initial` | 练习把 `struct + 一组函数` 收成 `class` |
| 状态机（FSM，Finite State Machine） | `1-2Stepper-Initial`、`1-3State` | 对照 `class` 成员函数、`enum class` |
| 头文件防护、`extern`、`static inline` | `1-4RandomKnowledge` | 对照 `namespace`、`inline`、链接与名字修饰（name mangling） |
| 宏、`const`、GNU 扩展、`packed` / `aligned` / constructor 属性 | `1-5Extended` | 对照 `constexpr`、`decltype`、构造/析构、`alignas` |

结论先说清楚：

1. **不要从零开始学编程。** 变量、循环、指针、结构体、编译链接这些不要再走一遍。
2. **也不要把 C++ 当成「C 再加 class」。** 现代 C++ 真正要换的是资源管理思路：RAII（Resource Acquisition Is Initialization，资源获取即初始化）。
3. 你已经玩过 GNU 的 `constructor` / `destructor` 属性，以及 `typeof`、语句表达式宏。C++ 里对应的是**语言正统能力**，不是编译器私货。

ISO C++ 基金会（Standard C++ Foundation）对「已经会 C 的人」的官方态度是：先把 C++ 当 **better C** 用起来，再按需加特性。见 [Learning C++ if you already know C](https://isocpp.org/wiki/faq/c)。

## 2. 学习原则（防止学成百科全书）

1. **读代码优先，写大项目靠后。** 你学 C++ 是因为仓库里已经有 C++ 源码，不是为了从零造一个框架。
2. **先认语法，再谈设计。** 模板元编程（template metaprogramming）、完美转发（perfect forwarding）、协程（coroutine）全部划到「以后再说」。
3. **能用标准库就不要手搓。** `std::vector` 对上你熟悉的动态数组；`std::string` 对上 `char[]`；智能指针对上 `malloc` / `free`。嵌入式固件里可能仍用手写缓冲，那是场景限制，不是否定标准库。
4. **宏能少则少。** 你已经知道宏要加括号。C++ 里常量用 `constexpr`，短函数用 `inline` / 模板，比宏更安全。
5. **编译器用你已经在用的 GCC（GNU Compiler Collection）。** 把 `gcc` 换成 `g++` 即可。在线对照汇编用 [Compiler Explorer](https://godbolt.org/)。

### 建议的能力边界（学到这里就可以停）

**要会认、会改：**

- `class` / `struct`、访问控制、构造函数（constructor）、析构函数（destructor）
- 引用（reference）与指针的差别
- `namespace`、函数重载（overload）
- `enum class`
- `auto`、范围 for（range-based for）
- RAII 与 `std::unique_ptr` 的基本用法
- 模板函数 / 模板类的**阅读**（不必会写复杂模板）
- 继承与虚函数（virtual function）的**阅读**（固件里常见）
- `extern "C"` 与 C / C++ 混编
- 常用标准库：`vector`、`string`、`array`、`optional`（C++17）

**明确先不学：**

- 模板元编程、SFINAE、Concepts 深水区
- 异常安全层级、自定义分配器
- Boost 全家桶
- 并发内存模型细节
- C++20 Modules / Ranges / Coroutines 的实现原理

## 4. 四周路线（结合你现有代码）

每周一个主题。每主题：**读一小段 → 对照自己的 C 文件想一遍 → 写一个小于 80 行的实验**。不要开新大项目。

### 第 1 周：better C，先把编译和类型拧紧

**读**

- ISO FAQ：[已经会 C 怎么迁](https://isocpp.org/wiki/faq/c)
- Microsoft：[欢迎返回 C++](https://learn.microsoft.com/zh-cn/cpp/cpp/welcome-back-to-cpp-modern-cpp) 前半（智能指针之前即可）
- LearnCpp：跳过变量/循环/函数入门；看引用、`const`、重载、`namespace`

**练**

- 把任意一个 `.c` 改名为 `.cpp`，用 `g++ -std=c++17` 编译。
- 记录报错：未声明函数、`void*` 隐式转换、`class` 当标识符……这些就是 C 与 C++ 的缝。
- 用 `constexpr` 换掉一个简单 `#define` 常量（对照你在 `1-5Extended/extend_syntax.c` 里对宏括号的教训）。

**本周停在：** 能解释「为什么 C++ 不许 `int *p = malloc(...)` 不写强制转换」。

### 第 2 周：class、构造析构、RAII

这是从 C 到 C++ **唯一必须换脑子**的一周。

**读**

- Tour 第 3 版：类、构造、析构相关章节
- 或 LearnCpp：classes、constructors、destructors
- 对照你已经写过的 GNU 属性：`constructor` / `destructor` 是「进程级钩子」；C++ 的构造/析构是「对象生命周期钩子」

**练：把 PID 收成类**

现有 `1-1PID_Initial` 是 `struct + 一组函数`。目标形态（示意，不必抄进原项目）：

```cpp
class PidController {
public:
    /* 用构造函数把增益与积分限幅一次绑死，避免先声明后忘记初始化 */
    PidController(float kp, float ki, float kd, float i_limit);

    /* 推进一个采样周期，返回控制量 */
    float update(float error, float dt);

    /* 清积分，对应原来可能散落的 reset 函数 */
    void reset();

private:
    float kp_;
    float ki_;
    float kd_;
    float i_limit_;
    float integral_;
    float prev_error_;
};
```

体会三件事：

1. 数据与操作绑在一起，调用处不再传来传去一个 `ctx` 指针（当然指针/引用仍可用）。
2. 构造函数替代「先 memset 再手动填字段」。
3. 如果以后 PID 内部有堆缓冲，析构函数负责释放 → 这就是 RAII。

**本周停在：** 能说出 RAII 和 `malloc`/`free` 配对相比，到底防的是哪类 bug。

### 第 3 周：能读固件 / 项目里的 C++ 惯用语

你在 `1-2Stepper-Initial/Doc/04_项目文件索引与学习路径.md` 里已经把 Marlin 标成外部参考。固件 C++ 通常不是「纯现代范本」，但语法密度很高，适合练读。

**读（认语法，不追设计）**

- `enum class` vs 你在 `1-3State/L1_room.h` 里的普通 `enum`
- 继承与 `virtual`：看到基类指针调用，知道会走虚表（vtable）即可
- 函数重载、默认参数
- 模板：看到 `template<typename T>` 能把它脑内展开成「对某种类型生成一份函数/类」
- `auto`、范围 for、lambda（lambda expression，匿名函数对象）看到不慌

**练**

- 打开 Marlin 的运动相关 `.cpp`（你文档里已写路径：`Marlin/src/gcode/motion/G0_G1.cpp`）：[github.com/MarlinFirmware/Marlin](https://github.com/MarlinFirmware/Marlin)
- 只做阅读笔记：标出 `class`、`namespace`、`inline`、模板、`#ifdef`。不要试图改 Marlin。

**本周停在：** 打开一份陌生 `.cpp`，能判断「这是数据类 / 这是有虚函数的接口 / 这是模板工具」。

### 第 4 周：标准库扫货 + C/C++ 混编

**读**

- Tour 或 LearnCpp：`std::vector`、`std::string`、`std::array`、`std::unique_ptr`
- [混编 FAQ](https://isocpp.org/wiki/faq/mixing-c-and-cpp)
- 欧长坤教程目录扫一眼 C++11/14/17 特性名单，只点开你本周碰到的

**练**

- 用 `std::vector` 代替一块手动 `malloc` 的数组（主机侧仿真即可，不必上 MCU）。
- 写一个 C 头文件，用 `__cplusplus` + `extern "C"` 包起来，让 `.c` 与 `.cpp` 同时包含。你在 `declaration.h` 里已经熟悉头文件防护，这是同一套纪律的 C++ 延伸。

```cpp
#ifdef __cplusplus
extern "C" {
#endif

void gcode_parse_line(const char *line);

#ifdef __cplusplus
}
#endif
```

**本周停在：** 链接期再出现 `undefined reference to foo` 时，能想到「是不是一边 mangling、一边没 `extern "C"`」。

### 可选第 5 周：对照本仓库做一次「翻译」

选一个小模块，**不要重写整个项目**：

| 候选 | 翻译重点 |
|---|---|
| `1-3State` 房间状态机 | `enum class` + `class Room` + 成员函数 `process_event` |
| `1-2` 压力稳定判定 | 把阈值和窗口做成类型，构造时注入 |
| `1-5` 的 `typeof` 宏 `max` | 改成函数模板 `template<typename T> T max_of(T a, T b)` |

到这里就可以停。后面读到不懂的标准库名字，查 cppreference 即可。

## 5. C 脑内词典 → C++（读代码用）

| 你熟悉的 C | C++ 里更常见的写法 | 备注 |
|---|---|---|
| `struct Foo { ... };` + 一组 `foo_*` 函数 | `class Foo { ... }` | 纯数据仍可用 `struct` |
| `enum RoomState { ... }` | `enum class RoomState { ... }` | 避免枚举污染外围命名空间 |
| `foo_init(&obj)` | 构造函数 `Foo()` | 对象出生时必初始化 |
| GNU `constructor` 属性 | 全局对象构造 / `std::once_flag` 等 | 语义层级不同，不要混为一谈 |
| `malloc` / `free` | `std::unique_ptr` 或容器 | 嵌入式无堆场景可以继续静态分配 |
| `char buf[N]` + `strlen` | `std::string` / `std::string_view`（C++17） | 底层协议解析仍可能用裸缓冲 |
| 动态数组 + `realloc` | `std::vector` | 主机工具链优先用它 |
| `#define MAX 8` | `constexpr int kMax = 8;` | 有类型、可调试 |
| `typeof`（GNU） | `decltype` / `auto` | 标准写法 |
| 语句表达式宏 | `inline` 函数或函数模板 | 无副作用重复求值问题 |
| `static inline` 放头文件 | `inline` 函数；模板本就适合头文件 | 链接规则更严 |
| `__attribute__((packed))` | 仍可用；或 `#pragma pack` | 与硬件寄存器布局打交道时两边都会出现 |
| `__attribute__((aligned(n)))` | `alignas(n)` | 标准关键字 |
| 零长数组 / 柔性数组成员 | 非惯用 C++；用 `vector` 或尾部分配 | 读 C 风格 C++ 时仍可能见到 |
| `qsort` | `std::sort` | 见 Stroustrup 那篇 *New Language* 论文 |
| `void *` 泛型 | 模板 | 类型在编译期保留 |
| 函数指针回调 | lambda / `std::function` | 固件里函数指针仍然非常常见 |
| `.name = "x"` 指定初始化 | C++20 起对聚合类型有限制版指定初始化 | C++17 项目里可能仍是按成员顺序初始化 |

## 6. 打开一份 C++ 源码时的扫描顺序

遇到陌生 `.hpp` / `.cpp`，按这个顺序扫，避免一上来栽进模板深水：

1. `#include` 和 `namespace`：这文件依赖谁、名字空间叫什么。
2. `class` / `struct` 列表：哪些是纯数据，哪些有成员函数。
3. 构造函数参数：对象出生需要什么。
4. `public` 接口：调用方真正能用的就这些。
5. 有没有 `virtual`：有则存在运行期多态。
6. 有没有 `template`：先当「类型参数化的宏，但是类型安全」。
7. `extern "C"`：这是 C 边界。
8. 宏和 `#ifdef`：嵌入式 C++ 里仍然很多，你已经熟。

读不懂某一行时，把符号贴进 cppreference，而不是把整本书翻一遍。
