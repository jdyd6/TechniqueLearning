## 0. 你的印象只对了一半

「一个数据里装着下一个数据的指针」——这句话语法上没错，但把链表说成「带尾巴的结构体」，等于把手术刀说成「一块带刃的铁」。

数组（array）卖的是**下标随机访问**。  

链表（linked list）卖的是**已经握在手里的节点，可以做局部改写**。

`next` 只是零件。真正值钱的是：

1. 插入 / 删除时，**payload（有效载荷）不用搬家**。
2. 别人手里的节点指针，**不会因为别处插入而失效**。
3. 整段子链可以 **splice（拼接 / 挪走）**，复杂度与节点个数无关。

这三件事数组做不到，环形缓冲区也做不到。所以链表重要——但重要的场景很窄，用错地方会比数组慢一个数量级。

---

## 1. 数组搬砖，链表改箭头

在数组中间插入，后面的元素必须整体挪位：

```
原：  [10][20][30][40][  ]
插入 99 到下标 2：
      [10][20][99][30][40]     ← 30、40 整块 memmove
```

在链表里，节点散落在堆上（heap），彼此只靠指针认路。插入只改箭头：

```
原：  10 → 20 → 30 → 40
在 20 后面插入 99：
      10 → 20 → 99 → 30 → 40   ← 30、40 原地不动
```

对应的 C 就是几行指针赋值，不是循环搬数据：

```c
/* 已知 pred 指向 20，node 是新节点 99 */
node->next = pred->next;   /* 99 先抓住 30，否则 20 一改箭头，30 就丢了 */
pred->next = node;
```

**赋值顺序是硬约束：** 必须先让新节点抓住原后继，再改前驱的 `next`。两行对调，原后继从链上消失，还不一定能 `free`，属于典型泄露。

**本质：** 链表操作改的是「谁指向谁」，不是「内存里这一段字节往哪挪」。

这就是为什么教科书爱说插入删除是 O(1)（constant time，常数时间）。下面立刻给它泼一盆冷水。

---

## 2. O(1) 有前提：你已经握着那个节点

找值仍是 O(n)。从 `head` 走到目标节点，该走多少步还是多少步。

| 操作 | 数组 | 单链表 | 双向链表（已有节点指针） |
| --- | --- | --- | --- |
| 按下标读 | O(1) | O(n) | O(n) |
| 按值查找 | O(n) | O(n) | O(n) |
| 已知位置插入 / 删除 | O(n) 搬迁 | 还需前驱 | **O(1) 改指针** |
| 拼接两条容器 | O(n) 拷贝 | 改尾指针 | 改端点指针 |

所以链表的「快」从来不是「我随便插很快」，而是：

> 系统里**已经有一个指向该对象的句柄（handle）**，现在要把它挂进 / 摘出某个集合。

内核里的进程、驱动里的请求、内存池里的空闲块，全都满足这条。面试题里「先遍历再删」并不满足——那只是在练指针，不是在用链表的长处。

---

## 3. 威力落地的三件事

### 3.1 Splice：搬家不拷贝

把链表 A 的一段剪下来接到 B 上，payload 一个字节都不用复制。数组要 `memcpy` 整段，链表只改端点指针。

这是任务迁移、定时器分层、把「待处理」整批变成「处理中」时，链表能打数组的地方。

### 3.2 稳定句柄：别处插入不让别人的指针失效

数组一 `realloc`（重新分配），所有旧指针作废；中间插入，后面元素的下标全变。  

链表在别处插入 / 删除，**没被删掉的节点地址不变**。

于是你可以：

- 在哈希表（hash table）里存节点指针，链表负责顺序；
- 让一个对象同时被多个子系统盯着，插入队列不会把别人的指针弄飞。

环形缓冲区做不到这件事：槽位是环形复用的，指针 / 下标的含义会随读写指针转走而失效。

### 3.3 Intrusive list（侵入式链表）：链嵌在对象里

教材写法是「节点包数据」：

```c
struct Node {
    int data;
    struct Node *next;
};
```

系统写法是「数据含链」——Linux 内核的 `list_head` 就是这个思路：

```c
struct list_head {
    struct list_head *next;
    struct list_head *prev;
};

struct Job {
    int cmd;
    struct list_head link;   /* 链在结构体里面，不是结构体装在链节点里 */
};
```

从 `&job->link` 找回 `Job`，靠 `container_of`（容器倒推：已知成员地址，减偏移得到结构体地址）。第 3 步会把它写具体。

一个对象可以嵌**多条**链：运行队列一条、等待队列一条、调试链表再一条。这不是炫技，是「同一份 payload，多种集合身份」。教材那种 `Node` 包一层，想同时挂两条链就要拷贝或再包一层，立刻变丑。

### 3.4 Free list（空闲链表）：分配器本体就是一条链

内存池（memory pool）里，空闲块的 `next` 指向下一块空闲。`alloc` 是头删，`free` 是头插，都是 O(1)，热路径零次 `malloc`。

堆分配器、网络 mbuf、嵌入式对象池，底层几乎都是这条链。你刚才学的环形缓冲区管「固定槽位的流水」；空闲链表管「这块对象现在归谁」。

---

## 4. 和环形缓冲区怎么分工

两者都是队列的实现，但卖点相反。

|  | 环形缓冲区 | 链表 |
| --- | --- | --- |
| 容量 | 编译期 / 初始化时定死 | 随插入增长（或受池子上限约束） |
| 内存 | 连续，cache locality（缓存局部性）好 | 节点分散，pointer chasing（指针追逐）容易 miss |
| 中间摘除 | 基本不支持 | 已有节点则 O(1) |
| 分配 | 无 | 教材版每节点 `malloc`；嵌入式应改成池 |
| 典型工作 | 采样、DMA、字节流、SPSC 队列 | 待办集合、定时器、对象池、可取消的请求 |

固件里常见组合：

- 中断把原始字节推进 ring buffer；
- 解析出一条「请求」后，把请求对象挂进 linked list（可取消、可按优先级摘）；
- 请求对象本身来自 free list，不在热路径 `malloc`。

**会用链表，不等于处处用链表。** 固定长度的 FIFO（First In First Out，先进先出），环形缓冲区几乎总是更好的答案。

## 第 1 步：单链表指针手术

打开 `SECTION_1`。目标不是「能跑」，是每一行赋值都能说出改了哪根箭头。

### 1.1 节点长什么样

```c
typedef struct Node {
    int data;
    struct Node *next;
} Node;
```

空表就是 `Node *head = NULL;`。只有一个指针变量 `head`，它不是节点，它是「指向第一个节点的那根指针」。后面 `Node **` 之所以存在，就是因为有时要改的是 `head` 这根指针本身。

### 1.2 `node_new`：先做出一个孤岛

新节点此时不属于任何链，`next` 必须是 `NULL`。只申请内存、填字段，不改别人的指针。

```c
static Node *node_new(int data)
{
    Node *n = malloc(sizeof(*n));
    if (n == NULL) {
        return NULL;
    }
    n->data = data;
    n->next = NULL;
    return n;
}
```

### 1.3 `push_front`：新节点当头

```
之前：  head ──► [10] ──► [20] ──► NULL
要插 1：

1. n->next = *head      n 先抓住原头
         [1] ──► [10] ──► [20]
         head 仍指向 10

2. *head = n            再让 head 改口
         head ──► [1] ──► [10] ──► [20]
```

两行对调会丢失原头：`head` 先指向 `1`，而 `1->next` 还是 `NULL`，原链没人指，泄露。

```c
static void push_front(Node **head, int data)
{
    Node *n = node_new(data);
    if (n == NULL) {
        return;
    }
    n->next = *head;
    *head = n;
}
```

这里必须是 `Node **`：函数要改调用方的 `head` 变量。传 `Node *` 只能改副本。（只改了形参作用域复制出来的副本）

### 1.4 `push_back` 与 `Node **` 巡游

空表时，「指向第一个节点的那根指针」就是 `head` 自己。非空时，要改的是**最后一个节点的 `next` 成员**。这两种情况都是「找到一根值为 `NULL` 的指针，把新节点写进去」。

```
空表：  pp = &head，*pp == NULL，直接 *pp = n
        head ──► [n]

非空：  head ──► [10] ──► [20] ──► NULL
        pp 先是 &head，*pp 是 10，不是空
        pp = &(*pp)->next    现在 pp 指向 10 内部的 next
        *pp 是 20，不是空
        pp = &(*pp)->next    现在 pp 指向 20 内部的 next
        *pp 是 NULL，停下
        *pp = n              20.next 接到新节点
```

`pp = &(*pp)->next` 读成：**下一根需要被检查 / 改写的指针，就是当前节点的 `next` 成员本身**。`pp` 的类型是 `Node **`，它不指向节点，它指向「某根 `Node *`」。

```c
static void push_back(Node **head, int data)
{
    Node *n = node_new(data);
    if (n == NULL) {
        return;
    }

    Node **pp = head;
    while (*pp != NULL) {
        pp = &(*pp)->next;
    }
    *pp = n;
}
```

### 1.5 遍历打印

终止条件是 `p == NULL`。单链表有空尾巴，没有环。

```c
static void print_list(const char *tag, const Node *head)
{
    printf("%s", tag);
    const Node *p = head;
    while (p != NULL) {
        printf("%d -> ", p->data);
        p = p->next;
    }
    printf("NULL\n");
}
```

### 1.6 `reverse`：三指针拧方向

节点不搬家，只把每根 `next` 反过来。循环里**必须先保住后继**，再拧当前节点，否则后半段丢失。

```
开始：  prev=NULL, curr=10

        NULL     [10] ──► [20] ──► [30] ──► NULL
                 curr

第一步：next = 20
        10.next = NULL（指向 prev）
        prev = 10, curr = 20

        [10] ──► NULL
        [20] ──► [30] ──► NULL     ← 后半段靠事先保住的 next 还在

第二步：next = 30
        20.next = 10
        prev = 20, curr = 30

        [20] ──► [10] ──► NULL
        [30] ──► NULL

第三步：next = NULL
        30.next = 20
        prev = 30, curr = NULL  → 结束
        *head = prev            → head 指向 30
```

```c
static void reverse(Node **head)
{
    Node *prev = NULL;
    Node *curr = *head;

    while (curr != NULL) {
        Node *next = curr->next;
        curr->next = prev;
        prev = curr;
        curr = next;
    }
    *head = prev;
}
```

空表、单节点都能走这套代码：空表时 `curr` 一开始就是 `NULL`，`head` 被写成 `NULL`；单节点时 `next` 是 `NULL`，该节点的 `next` 拧成 `NULL`，`head` 仍指向它。

禁止递归。递归反转是在练函数调用，不是在练指针手术。

### 1.7 `find_value`：给 erase 提供句柄

真正的系统代码里，句柄往往本来就在你手里。练习里用按值查找模拟「我已经握着那个节点」。

```c
static Node *find_value(Node *head, int data)
{
    while (head != NULL && head->data != data) {
        head = head->next;
    }
    return head;
}
```

找不到返回 `NULL`。`erase` 必须能吞 `NULL`。

### 1.8 `erase`：改「指向受害者的那根指针」

教材写法会拆成「如果是头，改 `head`；否则改前驱的 `next`」。两套代码，边界 knocks 你。统一成：找到那根指向 `target` 的指针，把它改接到 `target->next`。

删中间节点 20：

```
head ──► [10] ──► [20] ──► [30] ──► NULL

pp = &head          *pp 是 10，不是 20
pp = &node10.next   *pp 是 20，命中
*pp = 20.next       即 node10.next = 30
free(20)

head ──► [10] ──► [30] ──► NULL
```

删头节点 10：

```
pp = &head          *pp 就是 10，命中
*pp = 10.next       即 head = 20
free(10)
```

头和中间走同一条 `*pp = target->next`。这就是 `Node **` 的全部意义。

```c
static void erase(Node **head, Node *target)
{
    if (target == NULL) {
        return;
    }

    Node **pp = head;
    while (*pp != NULL && *pp != target) {
        pp = &(*pp)->next;
    }
    if (*pp == NULL) {
        return;
    }

    *pp = target->next;
    free(target);
}
```

`free` 之后 `target` 立刻作废。调用方如果还留着这个指针，那是 use-after-free，不是链表的锅。练习里 `find_value` 的返回值用完即弃。

### 1.9 `destroy`：先保住后继再释放

```c
static void destroy(Node **head)
{
    Node *p = *head;
    while (p != NULL) {
        Node *next = p->next;
        free(p);
        p = next;
    }
    *head = NULL;
}
```

先 `free` 再读 `p->next` 是未定义行为。最后把 `head` 置空，避免调用方以为链还在。

### 1.10 过关标准

`main` 已经写好。填完函数后应看到：

```
build:   1 -> 10 -> 20 -> 30 -> NULL
reverse: 30 -> 20 -> 10 -> 1 -> NULL
erase 1: 30 -> 20 -> 10 -> NULL
erase20: 30 -> 10 -> NULL
destroy: NULL
```

还要能默画：`pp`、`*pp`、`(*pp)->next` 三者分别是谁。删头时 `pp` 等于 `&head`；删中间时 `pp` 等于某个节点内部 `next` 的地址。

## 第 2 步：双向循环 + 哨兵 + splice

打开 `SECTION_2`，关掉 `SECTION_1`。这一步把「是不是头 / 是不是空」从代码里消灭。

### 2.1 哨兵自环

```c
typedef struct DNode {
    int data;
    struct DNode *prev;
    struct DNode *next;
} DNode;
```

哨兵（sentinel / dummy node）不是数据节点，不释放。它把自己绕成环，表示空表：

```
空表：  sentinel.prev ──► sentinel ◄── sentinel.next
        （两根箭头都指自己）

有数据： sentinel ↔ 1 ↔ 2 ↔ 3 ↔ （回到 sentinel）
```

遍历终止条件是 `p != sentinel`，**不是** `p != NULL`。循环链表没有空尾巴，写成 `NULL` 会转圈直到你自己晕。

```c
static void dlist_init(DNode *sentinel)
{
    sentinel->prev = sentinel;
    sentinel->next = sentinel;
    sentinel->data = 0;
}

static int dlist_is_empty(const DNode *sentinel)
{
    return sentinel->next == sentinel;
}
```

### 2.2 `insert_after`：四根箭头

已知 `pos`，把 `node` 插到它后面。先抓住原后继 `succ`，否则 `pos->next` 一改，后继就丢。

```
之前：  pos ↔ succ
插入 node：

1. node.prev = pos, node.next = succ     新节点两头先抓住人
2. pos.next  = node                      前驱改口
3. succ.prev = node                      后继改口
```

空表时 `pos` 是哨兵，`succ` 也是哨兵，插入后变成 `sentinel ↔ node ↔ sentinel`。非空、插头、插尾，都是这四行。这就是哨兵的报酬。

```c
static void dlist_insert_after(DNode *pos, DNode *node)
{
    DNode *succ = pos->next;

    node->prev = pos;
    node->next = succ;
    pos->next = node;
    succ->prev = node;
}

/* 插到当前尾部之后 = 插到哨兵前面 = 插到哨兵的 prev 后面 */
static void dlist_insert_tail(DNode *sentinel, DNode *node)
{
    dlist_insert_after(sentinel->prev, node);
}
```

`dnode_new` 与第 1 步的 `node_new` 同类，做出孤岛即可，`prev` / `next` 先空着，插入时会被覆盖。

### 2.3 `erase`：已知节点，不遍历

双向链表的胜场：节点自己带着前驱，不必再找。

```
之前：  pred ↔ node ↔ succ
之后：  pred ↔ succ
        node 的 prev / next 置空，交给调用方 free
```

```c
static void dlist_erase(DNode *node)
{
    DNode *pred = node->prev;
    DNode *succ = node->next;

    pred->next = succ;
    succ->prev = pred;
    node->prev = NULL;
    node->next = NULL;
}
```

调用方保证 `node` 不是哨兵。删哨兵等于把整张表的入口拆掉。

对比第 1 步：单链表删除必须先找到「指向它的那根指针」；双向链表节点自身就够。O(1) 的前提在这里终于齐了。

### 2.4 `splice_after`：剪一段，接到别处

把闭区间 `[first, last]` 从原位置剪下，接到 `pos` 后面。节点不释放、不拷贝、不改 `data`。`pos` 不得落在 `[first, last]` 内。

```
之前：
  ... old_pred ↔ first ↔ ... ↔ last ↔ old_succ ...
  ... pos ↔ new_succ ...

先剪：
  old_pred ↔ old_succ
  first ... last  暂时悬着，但它们内部互指还在

再接：
  pos ↔ first ↔ ... ↔ last ↔ new_succ
```

只动端点：`old_pred`、`old_succ`、`pos`、`new_succ`，加上 `first->prev` 与 `last->next`。中间节点的 `prev` / `next` 根本不用碰——这就是「搬家不拷贝」。

```c
static void dlist_splice_after(DNode *pos, DNode *first, DNode *last)
{
    DNode *old_pred = first->prev;
    DNode *old_succ = last->next;
    DNode *new_succ = pos->next;

    old_pred->next = old_succ;
    old_succ->prev = old_pred;

    pos->next = first;
    first->prev = pos;
    last->next = new_succ;
    new_succ->prev = last;
}
```

练习里的演示：A 上是 `1 ↔ 2 ↔ 3 ↔ 4`，把 `[2, 3]` 接到空表 B 的哨兵后面。结果 A 剩 `1 ↔ 4`，B 变成 `2 ↔ 3`。`2` 和 `3` 的地址不变，`data` 没被碰过。

### 2.5 打印与销毁

打印从 `sentinel->next` 走到再次遇到哨兵。销毁同样，哨兵留下并重新 `dlist_init`。

空表、删到只剩哨兵，必须和多节点走同一套 `insert` / `erase`，不许写 `if (empty)` 分支。若你写了特殊情况，说明哨兵没被用对。

### 2.6 过关标准

```
A build:     1 <-> 2 <-> 3 <-> 4 <-> (sentinel)
B empty? 1
B empty:     (sentinel)
A after cut: 1 <-> 4 <-> (sentinel)
B after add: 2 <-> 3 <-> (sentinel)
A erase 1:   4 <-> (sentinel)
```

对照实验：用数组做一次「中间删除 + 两段拼接」，数一数 `memmove` 的元素个数。差值就是链表存在的理由。

## 第 3 步：侵入式链表 + 对象池工作队列

打开 `SECTION_3`。全程**禁止**再对 `Job` 调用 `malloc` / `free`。链的手术直接复用第 2 步，只是节点类型换成 `list_head`。

### 3.1 链在对象里面

```c
struct list_head {
    struct list_head *next;
    struct list_head *prev;
};

struct Job {
    int cmd;
    int arg;
    struct list_head link;
};
```

第 1、2 步是「节点里装着数据」。现在是「数据里装着链」。`list_init` / `list_insert_after` / `list_insert_tail` / `list_erase` / `list_is_empty` 与第 2 步同构，只是把 `DNode *` 换成 `struct list_head *`，并且**不再有 `data` 字段**——链节点是纯挂钩。

`list_erase` 之后把节点收成自环（`node->next = node; node->prev = node;`），表示「暂时不属于任何链」。第 2 步置 `NULL` 也可以；自环的好处是误把已摘节点再 `erase` 一次，不会对 `NULL` 解引用。

### 3.2 `container_of`：从挂钩找回整颗对象

`work_list.next` 给你的是 `struct list_head *`，你要的是 `struct Job *`。

```
Job 在内存里：
  [ cmd ][ arg ][ link.next ][ link.prev ]
                ^
                你手里的 ptr

offsetof(struct Job, link) = 从 Job 起点到 link 的字节数
job = (Job *)((char *)ptr - 这个偏移)
```

```c
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

static struct Job *job_from_link(struct list_head *link)
{
    return container_of(link, struct Job, link);
}
```

`link` 不是 `Job` 的第一个成员，**禁止**把 `list_head *` 直接强转成 `Job *`。那是第 7 节那个「指飞」的坑。练习文件里宏已经写好，`job_from_link` 一行即可。

### 3.3 两根链，一个池

```c
#define JOB_POOL_LEN 8
static struct Job jobs[JOB_POOL_LEN];   /* 唯一的存储，启动时就在 */
static struct list_head free_list;      /* 空闲对象 */
static struct list_head work_list;      /* 待执行请求 */
```

```
启动后：
  free:  sentinel ↔ job0 ↔ job1 ↔ ... ↔ job7 ↔ sentinel
  work:  sentinel ↔ sentinel

submit 一次：
  从 free 头摘一个 → 填 cmd/arg → 挂到 work 尾

run_one：
  从 work 头摘一个 → 打印 → 还回 free 头

cancel：
  从 work 中间摘掉（O(1)，因为句柄就是 Job*）→ 还回 free
```

任意时刻，一个 `Job` 要么在 `free_list`，要么在 `work_list`，绝不在两条链上，也绝不「两头都不在却没人管」。

### 3.4 典型实现

```c
static void pool_init(void)
{
    size_t i;

    list_init(&free_list);
    list_init(&work_list);
    for (i = 0; i < JOB_POOL_LEN; i++) {
        jobs[i].cmd = 0;
        jobs[i].arg = 0;
        list_init(&jobs[i].link);
        list_insert_tail(&free_list, &jobs[i].link);
    }
}

static struct Job *job_alloc(void)
{
    struct list_head *link;

    if (list_is_empty(&free_list)) {
        return NULL;
    }
    link = free_list.next;     /* 头节点，哨兵的 next */
    list_erase(link);          /* 摘下，变成自环 */
    return job_from_link(link);
}

static void job_free(struct Job *job)
{
    job->cmd = 0;
    job->arg = 0;
    list_erase(&job->link);                 /* 从当前链摘下；已是自环则无害 */
    list_insert_after(&free_list, &job->link); /* 还回空闲链头部 */
}

static struct Job *submit(int cmd, int arg)
{
    struct Job *job = job_alloc();
    if (job == NULL) {
        return NULL;           /* 池耗尽：失败，已有工作不受影响 */
    }
    job->cmd = cmd;
    job->arg = arg;
    list_insert_tail(&work_list, &job->link);
    return job;
}

static int run_one(void)
{
    struct list_head *link;
    struct Job *job;

    if (list_is_empty(&work_list)) {
        return 0;
    }
    link = work_list.next;
    job = job_from_link(link);
    printf("run cmd=%d arg=%d\n", job->cmd, job->arg);
    job_free(job);
    return 1;
}

static void cancel(struct Job *job)
{
    if (job == NULL) {
        return;
    }
    printf("cancel cmd=%d arg=%d\n", job->cmd, job->arg);
    job_free(job);
}
```

`submit` 返回 `Job *`，就是那份稳定句柄。环形缓冲区做不到：槽位会复用，你不能安全地拿着「第 k 个槽」去取消。链表可以，因为对象地址不变，直到你把它还回池子。

`print_chain` 的遍历与第 2 步相同：`for (p = head->next; p != head; p = p->next)`，循环体内用 `job_from_link(p)` 取回 `Job`。

### 3.5 过关标准

```
free  init: [cmd=0 arg=0] ... （八个空闲对象）
work  init:
work  3job: [cmd=1 arg=10] [cmd=2 arg=20] [cmd=3 arg=30]
run cmd=1 arg=10
run cmd=2 arg=20
work  left: [cmd=3 arg=30]
cancel cmd=3 arg=30
work  none:
pool exhausted at submit #8
work  full: [cmd=100 arg=0] ... [cmd=107 arg=7]
run cmd=100 arg=0
...
free  back: [cmd=0 arg=0] ... （八个都回来了）
```

热路径零次 `malloc`。池耗尽时 `submit` 返回 `NULL`，已挂在 `work_list` 上的任务继续可跑。

## 写的时候专门盯这些坑

1. **丢头指针。** `head = head->next` 之前没保存旧头，节点泄露。
2. **先 `free` 再读 `next`。** 释放后必须立刻当这个地址不存在。
3. **删完节点，外部还留着它的指针。** 这是 use-after-free。
4. **环形哨兵上写成 `while (p != NULL)`。** 终止条件是「回到哨兵」。
5. **侵入式链表把 `list_head *` 强转成 `Job *`。** `link` 不是第一个成员时会指飞，必须走 `container_of`。
6. **`insert` 两行对调。** 新节点必须先抓住原后继，再让前驱改口。
7. **splice 的 `pos` 落在被剪区间里。** 端点会指乱，结果未定义。练习里 `pos` 是另一条链的哨兵，区间在 A 上，不会踩这个雷。

## 练完应该留下的判断力

以后看到「这里要不要用链表」，只问三句：

1. 我是否**已经握着**要动的那个对象？
2. 是否需要**中间插入 / 删除 / 取消 / 拼接**？
3. 节点是否必须稳定，且最好来自**对象池**而不是每次 `malloc`？

三句都「是」，用链表（优先侵入式）。  

只是固定容量 FIFO，用环形缓冲区。  

需要按下标乱序打、而且会整体搬迁也无所谓，用数组。

链表不是更高级的数组，它是另一种合同：用随机访问和缓存友好，换局部改写和稳定句柄。
